# Starlark LLB

This package exposes a curated, typed Starlark facade over
`github.com/moby/buildkit/client/llb`. The goal is to let a Starlark file
compose BuildKit's immutable LLB graph while keeping the actual BuildKit
objects, interface checks, marshaling and execution in Go.

It is **Starlark**, a deterministic Python-like configuration language, not
CPython. It supports functions, keyword arguments, immutable module globals,
`load()`, lists, tuples, dictionaries and comprehensions, but it is not a
general-purpose Python runtime.

## Starlark example

```python
load(
    "llb",
    "Image",
    "Platform",
    "Shlex",
    "WithCustomName",
    "Mkfile",
    "Scratch",
)

def go_builder(image):
    return Image(
        image,
        Platform(os = "linux", architecture = "amd64"),
        WithCustomName("go-builder"),
    )

builder = go_builder("golang:1.26")
compiled = builder.run(Shlex("go build -o /out/app ./...")).root()

# LLB file actions are values and can be chained onto a state.
result = Scratch().file(
    Mkfile("/build-info", 0o644, b"generated by Starlark")
)

# A Definition is available when the caller wants to marshal in Starlark.
definition = result.marshal()
definition_digest = definition.head()
```

Methods have both BuildKit's Go spelling and a snake-case alias, for example
`state.Run(...)` / `state.run(...)`, `state.AddEnv(...)` /
`state.add_env(...)`, and `exec.Root()` / `exec.root()`. Module-level
constructors retain BuildKit's Go names.

## Go embedding

The short form uses the built-in `load("llb", ...)` module:

```go
globals, err := llbstarlark.Exec(ctx, "build.star", source, nil)
if err != nil {
    return err
}

state, ok := globals["result"].(*llbstarlark.StateValue)
if !ok {
    return fmt.Errorf("build.star must define result as an llb.State")
}

definition, err := state.Unwrap().Marshal(ctx)
if err != nil {
    return err
}
// The native definition can be passed to BuildKit's client.
pbDefinition := definition.ToPB()
_ = pbDefinition
```

Alternatively, put the module in the predeclared environment and use
`llb.Image(...)` without a `load()` statement:

```go
globals, err := llbstarlark.Exec(
    ctx, "build.star", source, llbstarlark.Predeclared(),
)
```

Applications can load their own Starlark files through `ExecOptions.Loader`.
The callback receives the current `*starlark.Thread`; evaluate imported files
with that same thread so nested `load()` calls use the same module graph:

```go
loader := func(thread *starlark.Thread, module string) (starlark.StringDict, error) {
    filename, source, err := readValidatedModule(module)
    if err != nil {
        return nil, err
    }
    return starlark.ExecFileOptions(
        &syntax.FileOptions{}, thread, filename, source, llbstarlark.Predeclared(),
    )
}

globals, err := llbstarlark.ExecWithOptions(
    ctx, "build.star", source, nil,
    llbstarlark.ExecOptions{
        MaxSteps: 1_000_000,
        Loader:   loader,
        Print: func(_ *starlark.Thread, message string) {
            log.Print(message)
        },
    },
)
```

The package caches successful module loads per thread, freezes returned module
globals and reports cyclic loads. The application owns module-name validation
and filesystem access; do not join an untrusted module name to a directory
without validating it first.

`ExecOptions.MaxSteps` limits interpreter steps. Starlark evaluation also
needs an application-level memory/process boundary when scripts are untrusted:
a step budget is not a memory limit. The context passed to `Exec` or
`ExecWithOptions` interrupts evaluation when cancelled.

## Exported Go API

The package's public Go declarations are:

| Go symbol | Purpose |
| --- | --- |
| `Module` | Frozen `starlarkstruct.Module` containing the LLB builtins and constants. |
| `Load` | Loader for `llb` and `lumet.llb`. |
| `ModuleLoader` | Callback type for application-defined modules. |
| `ExecOptions` | Syntax, step-budget, print and module-loader configuration. |
| `Exec` / `ExecWithOptions` | Evaluate a Starlark file and return its globals. |
| `NewThread` / `NewThreadWithLoader` | Create a configured interpreter thread. |
| `Predeclared` | Fresh predeclared dictionary containing `llb`. |
| `StateValue` | Starlark value wrapping `llb.State`; use `WrapState` and `Unwrap`. |
| `ExecStateValue` | Starlark value wrapping `llb.ExecState`; use `Unwrap`. |
| `FileActionValue` | Starlark value wrapping `*llb.FileAction`; use `Unwrap`. |
| `DefinitionValue` | Starlark value wrapping `*llb.Definition`; use `Unwrap`. |
| `WrapState` / `WrapExecState` / `WrapFileAction` / `WrapDefinition` | Adapt native BuildKit values to Starlark values. |
| `WrapOption` | Inject a native option into predeclared globals; its interface family is checked when consumed. |

The wrapped native values have private fields. Starlark code cannot forge
invalid BuildKit values by assigning internal Go fields. Go applications can
extend the module by placing `WrapOption(nativeOption)` in predeclared globals.
Option constructors return opaque option values tagged with their BuildKit interface family
(`RunOption`, `ImageOption`, `MountOption`, etc.). A wrong-family option is
reported as a type error before calling BuildKit.

## Built-in Starlark module API

The names below are the actual module members exposed by `Module`, grouped by
function. Names preserve the BuildKit spelling unless explicitly noted.

### Sources and graph composition

`Scratch`, `Image`, `ImageBlob`, `Git`, `Local`, `HTTP`, `OCILayout`,
`OCILayoutBlob`, `Merge`, `Diff`, and `OCIPlatform`.

`Platform(os, architecture, variant = "", os_version = "")` is a Starlark
adapter for BuildKit's `llb.Platform(ocispecs.Platform)` constraints option.
`OCIPlatform(...)` creates a platform value for the `State.Platform` method.
The distinction matters: BuildKit's `Platform` function returns an option,
not an OCI platform struct.

### State methods

`Run`, `File`, `With`, `AddEnv`, `AddEnvf`, `DelEnv`, `Dir`, `Dirf`,
`User`, `Hostname`, `WithCgroupParent`, `Network`, `Security`,
`Platform`, `Reset`, `Requires`, `AddExtraHost`, `AddUlimit`,
`SetMarshalDefaults`, `WithImageConfig`, `Marshal`, `Env`, `GetArgs`,
`GetDir`, `GetEnv`, `GetHostname`, `GetNetwork`, `GetPlatform`, and
`GetSecurity`. Snake-case aliases are available for these methods.

`Marshal` returns a `DefinitionValue`; its Go `Unwrap()` method returns the
native `*buildkitllb.Definition`. From Go, call `Definition.ToPB()` before
passing the graph to a BuildKit client.

### ExecState and file actions

`ExecState`: `Root`, `AddMount`, `GetMount` (plus snake-case aliases).

Module-level file actions: `Copy`, `Mkdir`, `Mkfile`, `Symlink`, `Rm`.

A `FileActionValue` supports the same chainable operations and `WithState`.
The resulting `CopyInput` wrapper can be used only as the input to another
`Copy`. This preserves BuildKit's sealed `CopyInput` contract.

### Constraints and state options

`WithCustomName`, `WithCustomNamef`, `WithExportCache`,
`WithoutExportCache`, `WithoutDefaultExportCache`, `WithDescription`,
`WithLinuxResources`, `Platform`, `CPUPeriod`, `CPUQuota`, `CPUShares`,
`CpusetCpus`, `CpusetMems`, `LocalUniqueID`, `MemoryLimit`,
`MemorySwapLimit`, `ProgressGroup`, `Require`, `Network`, `Security`,
`Reset`, `AddEnv`, `AddEnvf`, `DelEnv`, `Dir`, `Dirf`, `User`,
`Hostname`.

`WithLinuxResources` accepts keyword arguments `memory`, `memory_swap`,
`cpu_shares`, `cpu_period`, `cpu_quota`, `cpuset_cpus`, and
`cpuset_mems`. For example:
```python
state.marshal(WithLinuxResources(memory = 1073741824, cpu_shares = 512))
```

Most thin wrappers for BuildKit options accept positional arguments, mirroring
the corresponding Go function. Constructors that need structured input (such
as `Platform`, `OCIPlatform`, `ProxyEnv`, `Header`, and
`WithLinuxResources`) accept named keyword arguments.

## Scope and extension model

This is a high-level graph-building surface, not a reflection-generated mirror
of every declaration in `client/llb`. In particular, BuildKit's low-level
operation construction types (`Vertex`, `Output`, `NewExecOp`,
`NewFileOp`, custom `SourceOp` implementations, marshal caches and
low-level protobuf/marshal helpers) remain Go APIs. Callback-heavy facilities
such as `State.Async` and resolver injection such as `WithMetaResolver` also
remain Go-only until they have a deliberate Starlark callback contract.

When BuildKit adds a new public option or source, add a typed adapter to the
appropriate source/option registry and add it to this inventory. The shared
argument, option-family and wrapper code avoids changing the public bridge
architecture for each addition; it does not automatically expose newly added
BuildKit APIs.
